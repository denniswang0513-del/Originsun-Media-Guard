# 公布欄「行事曆」規劃（2026-09-14 草案，等 owner 拍板）

> owner 2026-09-14：「在公布欄規劃一個行事曆的功能，在這裡可以登記工作——用公司員工、專案人員、執行人員的角度來規劃。」
> 這份是**規劃**，還沒動程式。依據＝現況盤點（§0）；跟 Work OS 藍圖 §2「排班日曆→通告→工時預填」那條鏈對齊
> （ROADMAP N2），不另起爐灶。

## 0. 現況：跟「日期」有關的東西已經散在五個地方

| 東西 | 在哪 | 有什麼 | 缺什麼 |
|---|---|---|---|
| **拍攝場次** `crm_shoots` | 手機 CRM「行事曆」分頁（`m/views/calendar.js`）、`routers/api_shoots.py` | 日期／起迄時間／地點／人員 crew／器材預約／Google 日曆同步（`services/google_calendar.py` upsert／delete） | **桌機沒有畫面**；只有「拍攝」這一種事 |
| **我的一週** 計畫卡 | 工作台「今天與這週」（`ts-zone/plan.js`） | 一張卡＝某天、某案、做什麼（`timesheets` 列 status=plan） | 只能排自己（兼職排班例外）；沒時段、沒地點；別人看不到你排了什麼（團隊的一週看得到） |
| **團隊的一週** | 同上（`/me/team_week`） | 人×日格子：工時列＋計畫卡，疊拍攝場次與**已核准的假** | 只有週檢視、唯讀、不能從這裡登記 |
| **里程碑** `crm_project_milestones` | 團隊的一週「設定專案里程碑」 | 案子×週×標題×到期日×負責人×完成 | 不在任何日曆上以「日期」呈現 |
| **請假／假日表** `hr_leave_requests`／`hr_holidays` | 假勤 | 已核准的假（含 0.5 天）、國定假日／補班日 | 同上 |
| 付款里程碑 `payment_milestones` | 財務 | 到期日 | 只有財務在看，不進行事曆（§4 明確不做） |

結論：**不缺資料，缺一個「把這些放在同一張日曆上、而且能從日曆登記工作」的地方**。行事曆＝一個**讀取層**
（聚合上面那些）＋ **一種新的可登記事件**（§2「工作登記」），不是再做第六個獨立系統。

## 1. 三種人各自要什麼（owner 指定的三個角度）

### A. 公司員工（每個登入的人）
- 打開公布欄就看到**這個月公司在幹嘛**：哪天有拍攝、誰請假、國定假日、案子的里程碑到期日。
- **登記自己的工作**：「9/18 下午 剪 iWIN 年會 A-copy」——一格、三個欄位、十秒填完。登記完自己的一週就長出來，
  團隊的一週也看得到（跟現在的計畫卡同一份資料，不是另一套）。
- 「我的」篩選：只看跟我有關的（我被排的拍攝、我登記的工作、我負責的里程碑、我的假）。

### B. 專案人員（製片／AM，有 `crm_projects` 鑰匙）
- **以案子為中心看**：某一案從今天到結案的所有日期——拍攝場次、里程碑、我方排的工作，一條時間軸。
- **排人**：登記工作時可以指定別人（攝影師、剪接），一次多人、每人一個職務（攝影／燈光／剪接…）。
  這就是藍圖 §2 的「排班」：**專案 × 日期 × 人員 × 職務**。
- **衝突提醒**：排到的人那天請假、或已被別場拍攝排走 → 存之前標紅講清楚（不擋，人可以硬排）。
- 看**人的負載**：週檢視多一種「人員列」——每個人那週被排了幾天／幾件，一眼看出誰爆了誰閒著。

### C. 執行人員（現場／後期，主要用手機）
- **今天要做什麼**一頁看完：今天的拍攝（時間、地點、帶什麼、跟誰）＋ 今天被排的工作 ＋ 我負責、這週到期的里程碑。
  這就是「通告單」的第一版（藍圖 §2-2）——不另做表，日檢視就是通告。
- **做完一鍵變工時**：日檢視上每件被排的工作旁一顆「做了 ✓」→ 直接變成今天的專案紀錄（timesheets 列，
  預填案子／內容／整天或半天），只要補時數。這是藍圖 §3「排班→預填→確認」那條鏈的入口，N2 的第一步。
- 前一天晚上 Google Chat 收到「明天你有：…」（沿用 notifier；有排到才發，沒排不吵）。

## 2. 資料：一個新實體，其餘沿用

### `crm_schedule`（工作登記／排班；藍圖 §2 叫 `crm_project_schedule`，這裡用短名）
| 欄位 | 說明 |
|---|---|
| id | uuid4 hex |
| kind | `work`（一般工作）／`meeting`（會議／看片）／`out`（外出／勘景）／`other`；**拍攝不在這張表**——拍攝就是 `crm_shoots`，日曆上一起畫 |
| project_id | soft FK → crm_projects.id，**可空**（行政庶務、內部會議） |
| title | 做什麼（必填） |
| date / end_date | 起／訖（單日 end_date 空） |
| start_time / end_time | 'HH:MM'，空＝全天；另給「上午／下午」兩顆快捷鈕（存成 09:00–13:00／13:00–18:00，可改） |
| attendees | JSON `[{staff_id, name, role}]`；登記自己的工作＝一個人、role 空 |
| location_text | 自由文字（要場景庫再說） |
| notes | |
| status | `planned`／`done`／`cancelled`（字彙住後端 `core/schedule_logic.py`，前端從 options 拿——跟場次同規矩） |
| timesheet_ids | JSON，「做了 ✓」產生的工時列 id（§1-C；避免重複產） |
| google_event_id / synced_at / sync_error | 同場次那套（第二期才接） |
| created_by / created_at / updated_at | |

**跟「我的一週」計畫卡的關係**：計畫卡（timesheets 列 status=plan）**保留**，但改成 `crm_schedule` 的一個投影——
第一期做法最省：登記工作時若 attendees 只有自己＋單日，**同時**建一張計畫卡（同 `_planCreate`），卡上帶 `schedule_id`；
改／刪走 schedule 那邊連動。這樣工作台、團隊的一週、兼職排班一行都不用改，行事曆卻立刻有東西。
（二期把計畫卡整個換成讀 `crm_schedule`；藍圖 §3 的預填鏈也是接這張表。）

### 不新增的
- 拍攝＝`crm_shoots`（行事曆上「登記拍攝」直接開既有場次表單，桌機把 `m/views/calendar.js` 那套表單搬成共用模組）。
- 假＝`hr_leave_requests`（只畫已核准）；假日＝`hr_holidays`；里程碑＝`crm_project_milestones`（到期日）。

## 3. 後端

新檔 `routers/api_calendar.py`（prefix `/api/v1/calendar`）＋ 純規則 `core/schedule_logic.py`（字彙、衝突判定、上午／下午換算、
「做了 ✓」→ 工時列的形狀）。

| 端點 | 回什麼 | 守衛 |
|---|---|---|
| `GET /events?from=&to=&scope=me|project:<id>|all` | 統一事件流：`[{kind: shoot|schedule|leave|holiday|milestone, id, date, end_date, start_time, end_time, title, project_id, project_name, people:[…], location, status, mine: bool}]`；一趟撈五種、後端合併排序 | 登入＋`bulletin`（跟公布欄同一把） |
| `GET /options` | kind 字彙、status 字彙、人員（在職／合夥／兼職）、專案（進行中）、職務清單 | 同上 |
| `POST /schedule`、`PUT /schedule/{id}`、`POST /schedule/{id}/status` | 登記／改／完成／取消 | 自己＝綁定人員檔案即可；attendees 含別人＝`crm_projects` 鑰匙（同場次的寫入規矩） |
| `POST /schedule/{id}/done` | 「做了 ✓」：對呼叫者本人產一列 timesheets（work_date／project／task_note＝title／hours 由 body 帶，整天＝`HOURS_PER_WORKDAY`）；已產過回同一列 | 綁定人員檔案且自己在 attendees |
| `GET /conflicts?date=&end_date=&staff_ids=` | 那幾天這些人：已核准的假、已排的拍攝、已排的工作（存之前前端問一次） | 同 events |
| `GET /day?date=`（手機通告） | 本人那天：拍攝（含器材／地點／crew）＋被排的工作＋到期里程碑 | 綁定人員檔案 |

規則：
- 里程碑到期日、假、假日**唯讀**（去原本的地方改）；行事曆只負責畫和連過去。
- 私帳案（entity=mine）的專案名對非私帳讀者照 `_team_row` 那條線抹掉（只給案名不給 id；跟團隊的一週一致）。
- 衝突**只提醒不擋**（owner 決定人可以硬排）；請假衝突＝該人那天有已核准的假；拍攝衝突＝已在別場 crew。
- 通知（第二期）：每天 20:00 `notifier` 對明天有事的人各發一則 Google Chat（沿用 `social_daily`／里程碑那套 digest 機制）。

## 4. 前端

### 桌機：公布欄第三個子視圖「📅 行事曆」（`frontend/tabs/bulletin/calendar/`）
- 頂列：**月／週／日** 三顆 ＋ 篩選「我的／全公司／某一案（打字找）」 ＋ 「登記工作」「登記拍攝」兩顆。
- **月檢視**：格子日曆；每格最多 3 條（拍攝＝橘、工作＝藍、假＝灰、里程碑＝紫小旗、假日整格淡紅），多的「+N」；點格＝那天的清單。
- **週檢視**：兩種排法切換——「時間軸」（7 欄×時段）／「人員列」（人×日，PM 看負載；就是團隊的一週那張格子加上排班）。
- **日檢視**＝通告：那天所有事依時間排，拍攝展開器材／地點／crew；自己的工作旁「做了 ✓」。
- **登記工作**表單（彈窗）：做什麼（必填）／案子（打字找，可空）／日期＋結束日／上午・下午・全天・自訂時段／人員（預設自己；有 `crm_projects`
  鑰匙才能加別人，每人一格職務）／地點／備註。存之前打 `/conflicts`，有衝突在表單裡列出來再確認。
- 不做拖拉改期（一期）；改期＝點事件→表單改日期。

### 手機（`frontend/m/`）
- 既有「行事曆」分頁改成三段：**今天（通告）／本週／登記**；拍攝表單原樣、工作登記表單同桌機（欄位少、預設自己）。
- 「做了 ✓」只在手機日檢視與桌機日檢視出現（現場人員的主要動作）。

### 權限（RBAC 3 處同步：`core/auth.py ALL_MODULES`／`tab-config.js`／`user-mgmt.js`）
- **不開新鑰匙**：讀＝`bulletin`（公布欄本來就這把）；登記自己＝綁定人員檔案；排別人＝`crm_projects`。
- 只在 §5 二期「主管核可排班」真的要做時才考慮新 key。

## 5. 分期

| 期 | 做什麼 | 做完你看到的 |
|---|---|---|
| **一期（先做這個）** | `crm_schedule`＋`/api/v1/calendar`（events／options／schedule CRUD／conflicts）＋桌機月／週／日＋登記工作（連動計畫卡）＋手機「今天／本週／登記」 | 公布欄有一張全公司的月曆，拍攝、假、里程碑、大家登記的工作都在上面；自己十秒登記一件工作；製片能排人、排到請假的人會被提醒 |
| **二期** | 「做了 ✓」→ 工時列；前一晚 Chat 提醒；工作登記同步 Google 日曆（沿用場次那套）；人員列負載視圖 | 現場人員早上手機看今天、晚上按一下就是工時；老闆在 Google 日曆也看得到 |
| **三期（＝ROADMAP N2）** | 通告單分享連結給外部人員（token 制）、排班→預填→主管週結核可、排班 vs 實際工時對照 | 藍圖 §3 那條鏈完整 |

一期估 `crm_schedule` 表＋一支 router＋一個純規則檔＋桌機子視圖＋手機分頁改版，測試照 `_srcscan`＋純函式規則；
上線走 startup migration（`ALTER … IF NOT EXISTS` 那個迴圈），不動既有表。

## 6. 明確不做
- Google 日曆**反向**改回系統（跟場次同一條線）。
- 甘特圖、拖拉改期、資源（車輛／棚）預約、付款里程碑上日曆（財務的事，留在財務）。
- 審核流程（一期登記即生效；藍圖 N0 的極簡審核落地後再接）。

## 7. 要 owner 拍板的四件事
1. **位置**：放公布欄（你指定的）——但製片以案子為中心的檢視，要不要在「專案管理 → 專案詳情」也放一個「行事曆」分頁（同一份資料、只篩這一案）？建議要。
2. **排別人要不要經過本人同意**：一期建議「排了就算，本人收到通知」；要「本人確認」就等 N0 審核機制。
3. **外部人員**（不在人員檔案裡的 freelancer）能不能被排：一期建議只能填自由文字在備註；要正式排就先建人員檔案（狀態「兼職」）。
4. **Google 日曆**：工作登記也同步到公司共用日曆（跟拍攝一起），還是只同步拍攝？建議二期一起同步，日曆上顏色分開。
