### BUG-1：排程／分散式轉檔／失聯改派在本機的 enqueue 從未執行（coroutine 裸呼叫被丟掉）
1. 現象       core/scheduler.py:236、core/scheduler.py:411、core/dispatch_reconcile.py:135 三處
              `enqueue_job(req, ...)` 沒有 await。觸發條件：排程到期（非分散式）、分散式轉檔本機份額、
              失聯改派給本機。實際：任務沒進佇列；`dispatched += 1`／`return True` 仍算成功，排程的
              next_run 已推進、one-shot 已 disable → 那一次排程永久遺失。預期：任務進佇列。
              旁證：pytest 基準輸出 `core/scheduler.py:411: RuntimeWarning: coroutine ... was never awaited`；
              pyright reportUnusedCoroutine 正好三筆。
2. 根因       `core/worker.py:79` 的 `enqueue_job` 自 v1.9.8（0ea38615）起是 `async def`。這三個呼叫端
              （`dispatch_distributed_transcode`、`_check_and_dispatch`、`post_transcode`）是 sync 函式，
              由 `run_scheduler` 以 `asyncio.to_thread` 跑在執行緒上，裸呼叫只建出 coroutine 物件，沒有任何
              loop 會執行它。`core/drone_watcher.py:413` 同情境用的是正確橋接
              （`asyncio.run_coroutine_threadsafe(enqueue_job(...), loop).result(timeout=30)`）。
3. 影響範圍   呼叫端：`_check_and_dispatch`（run_scheduler 每 60s）、`dispatch_distributed_transcode`
              （`_check_and_dispatch` 分散式分支 + `routers/api_*` 手動派發？→ grep：只有 scheduler 內部）、
              `post_transcode`（`_redispatch`）。同一份碼隨 OTA 到機隊（agent 端排程也吃到）。
              不碰 public_router／ota_manifest／requirements／schemas／雙定義路由 → 中。
4. 重現       新測試 `tests/unit/test_scheduler.py::TestCheckAndDispatch::test_dispatch_awaits_enqueue`：
              patch `core.worker.enqueue_job`（AsyncMock）+ 背景執行緒起主 loop 註冊 `state.set_main_loop`
              → `_check_and_dispatch()` → 斷言 `mock.await_count == 1`（目前 0，紅）。
              `tests/unit/test_dispatch_reconcile.py::test_post_transcode_local_*`：無主 loop → 期望 False
              （目前 True，紅）；有主 loop → await_count == 1。
5. 修法       A) 三處改成 drone_watcher 同款橋接；主 loop 沒起就 raise，走既有 except → warning、不計數。
                 scheduler 內兩處共用同檔 helper `_enqueue_from_thread`；dispatch_reconcile 內聯 4 行
                 （它被 scheduler import，反向 import 會繞圈）。預估 diff ~30 行（不含測試）。
              B) 三個函式改 async、`run_scheduler` 拿掉 to_thread → 動到整個 tick 模型與 5 支既有測試，diff > 100。
              C) 不修。
              選 A：最小 diff、與既有正確寫法一致、失敗路徑重用既有 except。
6. 驗證與回退 改 core/scheduler.py、core/dispatch_reconcile.py；第 4 欄兩支紅→綠；全套 3783 綠。
              回退：`git checkout core/scheduler.py core/dispatch_reconcile.py` + 刪新測試。
              閘門條款「修法需要改測試才能綠」的解讀：既有 `TestCheckAndDispatch` 5 支沒有主 loop，修完會走
              except → `count == 0` 而失敗。需要**加一個 autouse fixture 提供主 loop**，斷言本身一字不改
              （反而 `assert_called_once` 之外多了 `await_count`）。這是補測試鷹架、不是放鬆斷言 —
              條款原意是「別為了綠而改斷言」，這裡不違反；報告正文明示。
