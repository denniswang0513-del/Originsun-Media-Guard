# 工作追蹤：專案工時區塊 UI 重整規劃（2026-09-03）

> owner 七點需求：① 追蹤每個專案的工作狀況與細項、可回溯 ② 每個員工每日做了什麼
> ③ 員工自己記時數 ④ 類似專案時可回溯參考 ⑤ 儀表板 ⑥ 大家看到大家同一天在做什麼
> ⑦ 每天先規劃自己的工作與時數，之後有結果可以自己看。
> 前提（owner 已拍板）：**不審核**；Sheet 每小時拉、與系統填並行到切換日。

## 0. 一句話

把「工時」升級成「**工作**」：一列不只是幾小時，而是「誰、哪天、哪個案、做什麼、
**計畫幾小時／實際幾小時**」。同一份資料，從四個角度看（今日／我的一天／專案／人員），
再疊一個儀表板。

**以 CRM（內部 App）為主開發**（owner 2026-09-03）：新 UI 直接做在人事管理 › 「專案工時」
tab（改名「工作追蹤」），用 tab 的原生寫法（深色主題、`frontend/tabs/timesheets/`），員工也用
內部 App 登入來填（帳號＋`timesheets` 模組＋綁定人員檔案）。「我的一天」在 tab 裡以登入者
own-scope 呈現。**員工端網頁介面到時候再規劃**（owner 2026-09-03）：`/my.html`「我的工時」
與 `/hours.html` 維持現狀、不再投入；本規劃只做 tab。

## 1. 現在有什麼（不重做）

| 需求 | 已有 | 缺 |
|------|------|----|
| ③ 自己記時數 | /my.html「我的工時」：月列表、多列新增、改／刪 | 「計畫」那一半 |
| ⑥ 大家互看 | /hours.html 團隊月表（每人每週各案） | **按天**看：今天誰在做什麼 |
| ① 專案狀況 | 專案匯總＋明細（各人／各月／最近列） | 工作細項的時間軸、階段、可比較的分類 |
| ② 員工每日 | 人員月視圖（每人×每案彙總） | 逐日、逐項的檔案頁 |
| ④ 回溯參考 | 只有 suggest_projects（找不到時的相似名） | 「類似專案並排比較」 |
| ⑤ 儀表板 | burn 表 | 今日／本週／負載／漏填一眼看 |
| ⑦ 先規劃再回看 | 無 | 整段 |

資料底層 `timesheets`（日期／人／案／內容／小時／來源）已足夠承接 ①②③⑥；⑦ 要加
「計畫」；④⑤ 是視圖與計算，不加表。

## 2. 資料模型：只加兩欄

```
timesheets
  + planned_hours  Float   NULL   ← ⑦ 早上填的計畫；hours 留 NULL 到「完成」才填
  + work_type      String  NULL   ← ④ 跨案可比的分類（見 §3 決定 A）；Sheet 列與舊列 NULL
```

- 一列＝一個「工作項」。早上建：planned_hours=2、hours=NULL；完成時按「照計畫」→ hours=2，
  或改成 3。晚上「我的結果」＝計畫 vs 實際差異。**沒完成的計畫列不算工時**（hours NULL）。
- 不另開 work_plans 表：計畫與實際是同一件事的兩個時間點，分表會出現「計畫 3 列、實際 2 列
  怎麼對」的問題；同一列兩個數字沒有這問題。
- burn／匯總／團隊表只算 `hours`（實際）；計畫只在「我的一天」「今日看板」顯示。
- Sheet 拉進來的列 planned_hours=NULL、work_type=NULL —— 不影響既有一切。

## 3. 三個要 owner 決定的

**A. 工作分類 work_type 要不要、列哪些**
沒分類的話「類似專案回溯」只能比總時數與人；有分類才能比「拍攝 40h／剪接 120h／
動態 30h」這種真的有參考價值的形狀。建議一組固定選項（可在設定改）：
`前期企劃｜拍攝｜剪接｜動態／特效｜調光｜聲音｜會議溝通｜行政｜其他`。
員工填的時候是一個下拉，Sheet 舊列留空（回溯時標「未分類」）。

**B. 「類似專案」怎麼算**
- 自動：同客戶 ＋ 案名相似（既有 suggest_projects）＋ 總時數量級接近 → 列前 5 個，
  點進去並排比較。
- 手動：在專案檔案頁自己「加入比較」任意案。
建議兩個都做，自動只是推薦，比較永遠是人挑的。

**C. 計畫的顆粒度**
- 方案甲：早上填「案＋內容＋預計小時」每項（建議；跟實際同形，結果頁直接對）。
- 方案乙：早上只寫一句今天要做什麼＋總時數（更輕，但比不出差異）。

## 4. 視圖設計（一個頁，六個分頁）

```
人事管理 › 工作追蹤（tab；員工與管理員都在這裡）
┌ 今日 ┬ 我的一天 ┬ 專案 ┬ 人員 ┬ 儀表板 ┬ [管理員] 設定 ┐
```
權限：`timesheets` 模組＝進得了 tab、看得到今日／專案／人員／儀表板（大家互看，已拍板）；
「我的一天」要綁定人員檔案；「設定」只有管理員。要讓員工進來：使用者管理勾 `timesheets`＋綁定。

### 4.1 每日看板（⑥ ⑦）
owner 2026-09-03 兩次釐清：「大家看到大家」是要知道**彼此每天做了什麼**（協調與回顧用），
不是看時數；而且**未必會早上填** —— 最後的結果才是重點：每一天、每個人、做了什麼事，
大家都看得到。
- 這一頁的主角是**當天的工作項**（實際）：一人一欄，卡片＝案名／內容／時數。什麼時候填都行
  （當天、晚上、隔天補），填了就出現。
- 計畫是加分不是門檻：有人事先填了計畫，卡片先以「計畫 2h」出現、完成後變「→ 實際 3h」；
  沒填計畫的人直接出現實際。計畫可以填未來的日子，想排的人才排。
- 日期列（← 今天 →）可往前翻回顧任何一天、往後翻看已排的。
- 卡片只顯示做什麼；不排名、不把沒填的人標紅（那是主管層的事，§7）。
- 週模式：人 × 日 grid，一週每個人做了什麼一眼看。
- 手機：一人一段直式列表。

### 4.2 我的一天（③ ⑦）
- 上半：**今天的計畫**——多列 grid（案／分類／內容／預計小時），預設今天；「複製昨天的計畫」一鍵。
- 中間：每一項旁有「完成（照計畫）」「改實際小時」；臨時多做的直接「＋新增」。
- 下半：**今天的結果**——計畫 Σ vs 實際 Σ、每項差異、本週累計 vs 參考工時。
- 月曆條：哪幾天填了、哪幾天有計畫沒結果（漏填自見）。
- 既有「我的工時」月列表併進來當第二個 sub-tab（歷史／改／刪）。

### 4.3 專案（① ④）
- 清單：總時數／人數／預算／消耗／最後填報（已有），多「狀態」與「分類組成」小條。
- 專案檔案頁：
  - 摘要：總時數、人數、起訖（第一筆到最後一筆）、預算消耗、分類組成（拍攝／剪接／…）。
  - **時間軸**：按日／按週的工作項流水（誰、做了什麼、幾小時）—— 這就是「工作細項可回溯」。
  - 各人合計、各月走勢（已有）。
  - **類似專案**：自動推薦 5 個＋手動加入 → 並排表（總時數／起訖天數／人數／分類組成／每人）。

### 4.4 人員（②）
- 清單：本月合計／填了幾天／平均／每週（已有團隊月表）。
- 人員檔案頁：**逐日流水**（日期 → 當天工作項）、月曆熱圖（每天幾小時）、案別組成、
  近 12 個月走勢。管理員與本人看得到全部細項；其他人看得到（⑥ 已決定大家互看）。

### 4.5 儀表板（⑤）
一頁六格，全部是既有資料算出來的，不加填報：
1. 今天誰在做什麼（今日看板縮圖）　2. 本週全體時數 vs 參考（工作日×8）
3. 進行中專案 burn 前五（超預算標紅）　4. 漏填：昨天沒填的人、有計畫沒結果的人
5. 負載：每人本週時數條（過載／閒置）　6. 本月分類組成（拍攝／剪接／…）
圖用內建 SVG（不引外部圖表庫；做的時候套 dataviz 規範）。

### 4.6 設定（管理員）
既有的：Sheet 拉取、對映指定、預算、快速補登 —— 原封搬到這個分頁。

### 4.7 總表（owner 2026-09-03 追加：像發票總表那樣一列一列看、手動調細節與備註）
- 一個月所有列（每人每案每項），篩選在前端：人員／專案／來源（Sheet／手填）／關鍵字；欄頭可排序；匯出 CSV。
- **管理員**可逐列改：日期、專案（重新對映）、分類、內容、計畫／實際小時，＋**管理員備註**
  （`timesheets.note`，員工端 /my.html 不顯示）。一般成員看得到、改不了（`editable` 由後端給）。
- Sheet 列也能改：改過的列 `row_hash` 不變，下次拉取仍認得、不會再插一次；但 Sheet 那一格之後
  若也改了，會以新 hash 另插一列（兩邊都改＝兩列，總表上看得到、刪一列即可）。
- 套欄位與員工改自己的列是同一支 `services.timesheet_self.apply_update`，只差守衛（check_admin）與 404。
- 管理員備註只進管理員端點的 JSON（總表依 is_admin、抽查列）；看板／時間軸／員工頁／團隊頁一律不帶。
- Sheet 列不套「實際或計畫至少一個 > 0」（0 小時的 Sheet 列也能改、status 保留 import）。
- 端點：`GET /timesheets/rows?month=`、`PUT /timesheets/rows/{id}`、`DELETE /timesheets/rows/{id}`。

## 7. 兩個角度的檢視（2026-09-03）與調整

### 員工角度（攝影／剪接／助理，一天填一次的人）

| 會卡的地方 | 調整 |
|------|------|
| 每天早上「先規劃」是額外負擔，現場人員多半是被派、不是自己排 | 計畫**非必填**：沒計畫直接填實際也行；「複製昨天」「從最近的案帶入」「本週一次規劃」三顆快捷；沒填計畫的人結果頁只顯示實際，不顯示「0 計畫」 |
| 回想一天做了什麼最痛 | 時數快捷鈕 0.5／1／2／4／8；昨天沒填的在「我的一天」頂端一列補；輸入順序＝案 → 內容 → 時數（跟 Sheet 一樣） |
| 「大家看到大家」變成比較與壓力 | 今日看板只顯示**做什麼**，不顯示排名、不把「還沒填」標紅給全員看；**漏填與負載排名只給主管**（見下） |
| 分類多一步 | work_type 可不填；預設帶上一次同案的分類；下拉 9 個以內 |
| 專案名對不到案 | 下拉可搜尋、最近用過的在前、顯示「客戶_案名」原字；對不到照樣存，不擋人 |
| 結果頁像成績單 | 文字中性（「計畫 6h，實際 7.5h」），不出現「超時」「落後」字眼；差異只給本人看 |
| 手機 | 員工端網頁延後，但 tab 的「我的一天」要在手機寬度**可填**（單欄、大按鈕）—— P1 驗收項 |
| Sheet 期間重複填 | 列上標「Sheet」，今日看板同案同日已有 Sheet 列時提示「Sheet 已有，這裡不用再填」 |

### 主管角度（owner／製片 PM）

| 想看到的 | 調整 |
|------|------|
| 誰今天在哪個案、明天打算做什麼 | 今日看板加「明天」模式（只顯示計畫）與**週模式**（人 × 日 grid，一週的工作一眼看） |
| 誰過載、誰閒、誰沒填 | 儀表板拆兩層：**大家的**（今日、本週全體、本月分類組成）與**主管的**（負載排名、漏填名單、有計畫沒結果）；主管層只給管理員 |
| 哪個案沒人動 | 專案清單加「停滯」標記（進行中但 N 天沒工時，N 預設 7）；儀表板主管層一格 |
| 報價 vs 實際 | 專案檔案頁加「報價人日」對照（報價單有人日項目時；只帶人日不帶錢，藍圖 §3.5-1）—— P2 |
| 預算不想回 Sheet 改 | 專案檔案頁「改預算」（管理員），寫 budget_hours；Sheet 拉取不覆蓋已手改的 |
| 對映沒做完，專案頁會分裂 | 專案清單標「未對映」並可直接指定（沿用既有「指定專案」）；設定分頁保留 |
| 要交給會計／結算 | 專案與人員檔案頁「匯出 CSV」（月份或案）—— P3 |
| 類似專案的參考要「像」 | 自動推薦加一個條件：分類組成相似（有 work_type 才算得出）；沒分類的舊案只比總時數與人數 |

### 對階段的影響

- P1 加：計畫非必填＋三顆快捷、時數快捷鈕、手機可填、今日看板週／明天模式、Sheet 重複提示。
- P2 加：停滯標記、改預算、報價人日對照、專案清單「未對映」可指定。
- P3 加：儀表板主管層（負載／漏填／有計畫沒結果）、匯出 CSV、週一 digest。
- 不變：不審核、兩欄 model、六分頁。

## 6. 不做的

- 不做審核流（owner 拍板）。
- 不做打卡／上下班時間；計畫與實際都是「小時數」不是時段。
- 不做甘特圖／排班（那是 N2 排班日曆的事；做了之後「計畫」可由排班預填）。
- 不把錢帶進來（日費、成本回寫是 N2 後半，走 staff_rate_history）。
